# Judge harness corrections and boundaries

- The first independent TypeScript harness invocation failed because the judging directory lacked an ES module package marker. Adding `judging/package.json` corrected the judge harness. No submission dependency or source was changed for this.
- Initial exploratory combat probes used a shared HCF+punch binding, a move-ID substring and a second-hit scaling assumption that did not match every project's data. Final probes use a valid common rotation, the actual move names and a longer input-driven combo. Initial exploratory output is retained as `combat-probes-initial.json`; only the corrected `combat-spotchecks.json` is scored.
- C ignores confirmation during the initial title animation. The comprehensive menu probe now waits for the title and its input delay. A intentionally generates a showcase replay when no recording exists; the comprehensive menu probe exits through the actual pause menu. Neither was treated as a softlock.
- C's scene changes are asynchronous. Initial screenshots could catch an old match or a screen wipe. Final stage readiness also checks the requested stage; final C presentation captures use its original built-in scene entry points and wait for actual scene frames before freezing. Entrance-frame images were not used to allege absent screens or visual defects.
- Manual-frame combat captures advance original simulation inputs and presentation. They do not inject moves, hit events, combo values, damage or winners. Spacing, starting HP/meter and a near-expiry timer are controlled fixtures. B presentation is rendered once per simulation sample so cut-ins decay naturally. Results screens use the actual state of two attack-generated low-life KO rounds.
- Primary screenshots and the primary benchmark use the same full Chromium headless GPU configuration, viewport and fixed resolution setting. The earlier software-backend benchmark and two-minute keyboard gameplay remain logged separately; they are not mixed into the primary FPS score. A's backing canvas is smaller by design and is reported explicitly.
- Test config overrides in work copies only change judge viewport/report output and worker count. No submission source is edited. The originals are checked against their initial content manifests at final verification.
